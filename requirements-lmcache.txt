# requirements-lmcache.txt -- runtime source of truth for the LMCache service.
#
# Since the custom LMCache integration (see docs/lmcache-build.md), the PRODUCTION
# cache server runs INSIDE the custom derivative image (KVP_LAUNCH_MODE=docker in
# scripts/start-cache.sh). The image already carries the exact custom LMCache
# build (base 0.5.7.dev428 / commit 03ee5b82418b6bd44e424cdd46932d9346f43eb2
# plus downstream patches for upstream PR #4136 and #5972), compiled against the
# pinned PyTorch/CUDA/Python of the pinned vLLM runtime. The MP server and every
# model worker MUST run this same image build -- startup fails on any identity
# mismatch.
#
# The host-venv install (pip install -r requirements-lmcache.txt) remains only
# for diagnostics and development probes (kv mp_ping / ipc-test). It must match
# the SAME LMCache version as the image or the MP protocol breaks silently
# (historical incident: host 0.5.3 vs image 0.5.6 -> register_kv_caches
# timeouts). To install the identical build on the host:
#
#   pip install --no-deps /path/to/lmcache-<version>-*.whl
#
# where the wheel comes from live/lmcache-build/wheels/ produced by
# scripts/build-lmcache.sh. Do NOT install a PyPI lmcache here: it will not
# carry the two downstream patches.
#
# Runtime dependencies for such probes (versions are informational; the pinned
# image is authoritative in production):
#   lmcache  == the custom wheel built by scripts/build-lmcache.sh
#   openai   >= 1.0            (probe client)
#   zstandard>= 0.22           (lossless codec used in L2, KVP_L2_SERDE=zstd)
#   lz4      >= 4.3            (alternative lossless codec)
#   pyzmq    >= 25.0           (MP RPC channel to the cache server)
