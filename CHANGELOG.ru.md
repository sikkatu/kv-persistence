## Раунд 66 (мелкие правки + лимит распаковки + паритет лаунчеров)

* Мелкие правки (отдельный коммит по замечанию ревьюера): приоритет ключа в
  test-recovery.sh теперь окружение > общий канонический ключ > локальное
  зеркало (явный API_KEY никогда не перезаписывается); `kvp_curl` экранирует
  `\` и `"` до curl-конфига, чтобы ЛЮБЫЕ байты ключа доходили до сервера
  (сырые кавычка/бэкслэш раньше молча искажались); мёртвый `AUTH=()` в
  check-tp4-api.sh удалён; doc-комментарий env.sh разделён аккуратно.
* Лимит размера распаковки в compress_serde (отложенный пункт 1): до вызова
  кодека `plain_len` сверяется с буфером назначения И конфигурируемым
  потолком (`KVP_DECOMPRESS_MAX_BYTES`, по умолчанию 1 ГиБ); zstd получает
  `max_output_size`, lz4 — потоковый `max_length`. Лживый plain_len или
  кадр-бомба теперь дают чистый ValueError (cache MISS) без безразмерной
  аллокации. Ошибки кодеков оборачиваются в ValueError (контракт cache-MISS).
  6 новых тестов, включая настоящую zstd-бомбу.
* Тест паритета лаунчеров (отложенный пункт 2, шаг 1):
  `tests/test_launcher_parity.py` запускает ОБА лаунчера движка на docker-
  заглушке и сравнивает финальный `docker run` — капы, compilation-config,
  монтирования /w, /live и ключ через --env-file обязаны совпадать. Тест
  поймал (и этот коммит чинит) скрытое расхождение: цикл ожидания KV-лаунчера
  был захардкожен (`seq 1 300`, `sleep 10`) и игнорировал
  `WAIT_TRIES`/`WAIT_SLEEP`, которые лаунчер рецепта соблюдал — теперь оба
  их соблюдают.
* repro-round65.sh ревьюера превращён в `tests/test_manage_check_http.py`
  (сценарии A–F: check-tp4-api с ключом/без, status с верным/неверным
  ключом, exit 0 при мёртвом сервере, режим без авторизации, ключи со
  спецсимволами).

## Раунд 65 (kvp_curl: ключ по pipe — без файлов, без ps, без unbound-переменных)

* Подход раунда 64 с файлом `.curl-header` вызвал три регрессии — все
  исправлены по предложению ревьюера: файла с ключом больше нет вовсе.
  Маленькая `kvp_curl()` передаёт bearer-ключ по stdin-пайпу
  (`printf | curl -K -`; printf — встроенная команда bash, невидима в `ps`)
  и вызывает обычный `curl`, если ключа нет (документированный режим
  ALLOW_NO_AUTH на loopback).
* manage.sh / check-tp4-api.sh больше не падают с "LIVE_DIR: unbound
  variable" (они никогда не задают LIVE_DIR, а `-K "$LIVE_DIR/..."` из
  раунда 64 обращался к нему под `set -u`).
* Режим uva без авторизации снова работает: без ключа старый код вызывал
  `curl -K <отсутствующий-файл>` (exit 26), поэтому цикл ожидания никогда не
  мог завершиться успехом. `kvp_curl` без ключа не шлёт заголовок.
* manage.sh `status` при остановленном сервере больше не завершается с кодом 7
  под `set -e` (старый баг: `code="$(curl ...)"` убивал скрипт до ветки
  "not reachable"). Присваивание защищено.
* test-recovery.sh: header-файл из mktemp удаляется через `trap ... EXIT`
  (в /tmp не остаётся ключевого материала), а общий канонический ключ
  (`~/.config/kvp/api_key`) теперь ПОБЕЖДАЕТ устаревший `$PWD/live/api_key`.
* В kv-persistence env.sh добавлен тот же хелпер `kvp_curl()`; лаунчер движка
  использует его в цикле ожидания (файла `.curl-header` больше нет нигде).
* Тесты обновлены под контракт kvp_curl.

## Раунд 64 (один парсер, auth вне ps везде, отказ от сжатия восстановлен)

* ОДИН парсер env-файлов (`_kvp_seed_env_file` в scripts/env.sh) заменяет две
  расходящиеся копии `_tp4_seed`. Копия в start-all не проверяла идентификаторы
  и падала на комментарии с отступом ("  # X=1" -> "invalid variable name");
  оба вызывающих используют одну функцию с точной семантикой рецепта. start-all
  также сидирует tp4.env ДО загрузки слоя конфигурации, поэтому
  `LMCACHE_L2_SERDE=lz4|none` из tp4.env больше не игнорируется молча
  (lmcache-server.env предварительно выставлял zstd).
* Bearer-ключ убран из вывода `ps` ВО ВСЕХ скриптах (утверждение раунда 63 было
  неполным): uva-лаунчеры, manage.sh и check-tp4-api.sh всех 5 рецептов теперь
  используют `curl -K <chmod-600 конфиг>` вместо `-H "Authorization: Bearer
  ..."`; файлы `.curl-header`, которые писались, но не использовались, теперь
  подключены. test-recovery.sh также читает общий `~/.config/kvp/api_key`
  (работает вне каталога репо) и держит свой header-файл в /tmp, а не в каталоге
  данных кэша.
* Отказ от сжатия восстановлен в лаунчерах рецепта: `export LMCACHE_L2_SERDE`
  теперь происходит только когда НЕ задан ни один из LMCACHE_L2_SERDE /
  KVP_L2_SERDE / USE_LOSSLESS_SERDE — `USE_LOSSLESS_SERDE=0` и
  `KVP_L2_SERDE=none` снова доходят до identity gate (безусловный export
  раунда 63 перекрывал их zstd).
* `kvp up` передаёт запомненное расположение рецепта (`export RECIPE_DIR=`) —
  кастомный каталог клона больше не падает с "production recipe not found".
  `kvp` пишет сохранённые пути только при первом использовании или при явном
  указании (разовый `KVP_REPO=/tmp/x kvp status` не перезаписывает конфиг), а
  установщик ставит симлинк вместо копии (`git pull` обновляет команду).
* hotsplit_env.sh: shebang снова первый (комментарий пина совместимости был
  добавлен над ним).
* Тесты обновлены под новые контракты: дефолт кодека уступает переключателям
  отказа, auth идёт через curl-конфиг.
