## Не выпущено

## Раунд 48 (запуск без конфигурации)

* `bash scripts/run-vllm-with-persist.sh` в новом терминале не требует
  export и флагов: IMAGE резолвится из дайджеста рецепта (запоминается в
  `live/image`), MODEL_DIR — из `live/model_dir`/пина идентичности/
  `~/models`, `KVP_SAME_UID=1` ПО УМОЛЧАНИЮ (root-фолбэк:
  `KVP_SAME_UID=0`), кодек по умолчанию — lossless zstd
  (`USE_LOSSLESS_SERDE=0` для байт-точного raw).
* Единая таблица семантики кодека для env.sh / identity.py / _fold_serde
  (исполняемый тест): пусто -> zstd, `raw`/`none` -> явный raw,
  переключатель важнее конфига. Namespace кэша идентичен в bash и Python
  без единого export.
* Остатки 0.5.3 вычищены и из комментариев кода (доки — раунд 47).

## Раунд 47b (авто-детект наблюдаемости)

## Раунд 47 (документация + честность дашбордов)

* Все доки ссылаются на закреплённый **LMCache 0.5.6** (90 устаревших
  упоминаний `0.5.3` исправлено в README/docs EN/RU/ZH); исторические
  ссылки на старые баги апстрима теперь говорят «до 0.5.6» без
  устаревших номеров версий.
* GPU pre-flight свободной памяти выполняется **после** удаления старого
  движка (лаунчер) и **после** остановки обоих сервисов (test-recovery,
  сценарий B) — в раунде 46 проверка стояла слишком рано и отказывала из-за
  законной VRAM движка (78 ГБ на карту на эталонном хосте).
* Grafana: дашборд *LMCache coordinator* аннотирован — ему нужна
  телеметрия координатора многосерверного режима, в нашем односерверном
  репозитории он законно показывает «No data»; дашборд *LMCache*
  объясняет, что данные появляются только с `USE_OBSERVABILITY=1` на
  сервере кэша.
* Создан этот CHANGELOG (EN/RU/ZH) — заметки о раундах теперь здесь.

* Deployment-доки (EN/RU/ZH): правило порядка перезапуска.

## Раунды 45h–45j (same-UID режим + bash-ловушки)

* Режим `KVP_SAME_UID=1`: контейнер движка работает под
  `$(id -u):$(id -g)` (динамический UID, без root), кэши под `/tmp`.
* `HOME`/`USER`/`LOGNAME` задаются для любого UID (страховка при
  отсутствии записи в passwd).
* `PRODUCER_USER` должен быть литеральным присваиванием (ловушка bash
  `${var:+NAME=val}`), закреплено исполняемыми тестами.
* Проверка PID кэш-сервера перенесена под `PERSIST=true`.

## Раунды 45–45g (корень CUDA IPC + ipc-test)

* Корневая причина доказана на железе: `register_kv_caches` падает с
  `CUDA_ERROR_MAP_FAILED`, когда кэш-сервер не под root открывает
  GPU-память, созданную root в контейнере. Два решения: оба под root
  (`sudo`) или один UID (`KVP_SAME_UID=1`).
* Новый `scripts/ipc-test.sh` воспроизводит точный падающий шаг (~1 мин,
  без загрузки модели), подключён к pre-flight; поддержка `PRODUCER_USER`
  для same-UID пробы.

## Раунды 42–44 (версия LMCache + API-drift + диагностика)

* Pre-flight версии LMCache: хост и образ должны совпадать (0.5.6).
* Runtime-патчи адаптированы к API 0.5.6 (`dynamic_store`, `@`-суффикт
  соли в именах файлов нативен в апстриме).
* RPC-ping на уровне протокола (`mp_ping.py`), автоматическая диагностика
  кэш-сервера при смерти движка, `PYTHONFAULTHANDLER=1` при старте сервера.

## Раунд 41 и ранее

* Реальная живость = TCP-подключение (не просто живой PID).
* Гейт идентичности разделён на pre-launch проверку конфига и post-launch
  проверку аргументов контейнера.
* Только lossless-кэш (zstd/lz4/none, fp8/turboquant громко отвергаются),
  трёхъязычные доки, понятные сообщения об ошибках.
