## Раунд 58 (единый слой конфигурации + фикс регрессии общего ключа)

* Регрессия общего API-ключа исправлена (recipes): лаунчер теперь ВСЕГДА
  зеркалирует канонический `$HOME/.config/kvp/api_key` в `live/api_key` при
  каждом запуске, поэтому `manage.sh` / `check-tp4-api.sh` никогда не пишут
  «требуется ключ», когда ключ существует. Все пять лаунчеров рецептов
  используют единую архитектуру ключа; хелперы читают канонический файл
  первым и больше не нуждаются в `tr`/`head` (чтение на чистом bash).
* ЕДИНОЕ решение по кодеку: `start-all.sh` резолвит эффективный L2-кодек
  ОДИН раз (общий фолд) и передаёт одно значение кэшу и движку — пин кодека
  в identity.env больше не может развести две стороны по разным кодекам.
* ЕДИНЫЙ слой конфигурации: `start-all.sh` загружает cache.env /
  lmcache-server.env / identity.env ДО любых решений — PID-проверка кэша
  использует эффективный `KVP_CACHE_ROOT`, поэтому кэш на кастомном пути
  распознаётся как работающий. `run-vllm-with-persist.sh` теперь читает
  `tp4.env` рецепта (окружение выигрывает у файла), поэтому HOTSPLIT_* /
  MAX_MODEL_LEN / MAX_NUM_SEQS / MOE_BACKEND доходят до движка при запуске
  через `start-all.sh`.
* ЕДИНАЯ точка входа: `scripts/start-all.sh` в recipes делегирует в
  kv-persistence — одна команда работает из любого каталога.
  `run-tp4-hotsplit.sh` остаётся независимым лаунчером рецепта.
* Контрактный тест между репозиториями (`tests/test_cross_repo_contract.py`,
  recipes): семантика кодека, версия lmcache (0.5.6), порты, пины
  namespace и монтируемые файлы HotSplit обязаны совпадать — изменение в
  одном репо больше не может незаметно сломать другое.
* Документация по компрессии приведена к одному виду (EN/RU/ZH + комментарии
  конфигов): lossless-zstd — ДЕФОЛТ везде, lz4 — альтернатива, байт-точный
  сырой режим — только явный opt-out (`LMCACHE_L2_SERDE=none`).

* Вердикт приёмки восстановления — **PASS** в docs/final-report.*:

## Раунд 56 (общий API-ключ + динамический hotsplit по умолчанию)

* ОДИН API-ключ для ОБОИХ репо: оба лаунчера (kv-persistence + recipes run-tp4-hotsplit.sh /
  run-tp4-uva.sh) читают и пишут канонический файл
  `$HOME/.config/kvp/api_key` (переопределение: `KVP_API_KEY_FILE=`).
  Легаси-файл `live/api_key` мигрируется при первом запуске и остаётся
  зеркалом для старого инструментария.
* Динамические горячие/холодные эксперты по умолчанию в kv-persistence:
  лаунчер теперь монтирует `/w`-механизм рецепта (hotsplit.py,
  hotsplit_plan.py, numa_bind.py, sitecustomize.py, expert_hist_mix.json)
  и передаёт `PYTHONPATH=/w` + дефолты HOTSPLIT_* рецепта
  (HOTSPLIT_DYNAMIC=1, HOT_GIB=30). Отключение: `KVP_HOTSPLIT=0`.

  ветки `main`.
