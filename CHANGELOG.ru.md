## Раунд 62 (диапазоны float-параметров + свежие CI-цифры)

* Валидация float-параметров теперь проверяет НАСТОЯЩИЕ диапазоны план-кода
  на хосте: `HOTSPLIT_DYN_DECAY` — 0..1, `HOTSPLIT_DYN_MARGIN` — не меньше 1
  (границы `_dyn_float` в hotsplit.py). Раньше проверялся только числовой
  формат, поэтому `DYN_DECAY=2` / `DYN_MARGIN=0.5` проходили хост-проверку и
  отвергались внутри контейнера после загрузки модели. Диапазоны считаются на
  чистом bash (без внешних утилит, без fail-open).
* CI-цифры обновлены после фикса cross-repo пути: CI recipes теперь
  **336 passed + 7 skipped** (в примечании раунда 61 было 330+13);
  CI kv-persistence без изменений — 344 passed + 4 skipped. Доки ссылаются на
  актуальные цифры.

## Раунд 61 (путь cross-repo в CI, эквивалентность boolean, compatibility probe)

* Контрактные тесты между репозиториями в CI recipes теперь реально
  выполняются: тест сначала ищет checkout kv-persistence ВНУТРИ workspace
  (`RECIPES/kv-persistence`, раскладка GitHub Actions) и лишь потом в
  домашних путях разработчика. Шесть контрактных тестов больше не
  пропускаются в CI.
* Boolean-параметры HotSplit нормализуются в KV-лаунчере ровно как в
  лаунчере рецепта (`normalize_bool`: true/yes/on -> 1, false/no/off -> 0)
  ДО подключения общего модуля. Компоненты HotSplit сравнивают со строкой "1"
  (`HOTSPLIT_NUMA == "1"`), поэтому сырое `true` незаметно отключало функцию.
  Покрыты DYNAMIC / DRYRUN / NUMA / ALLOW_STATIC_FALLBACK / STRICT_HOOK /
  NUMA_STRICT / DYN_LOG.
* KV-лаунчер теперь выполняет ТОТ ЖЕ compatibility probe model-патчей, что и
  лаунчер рецепта (сшивка base_loader, определение model_loader.utils,
  `load_weights` у mimo_v2/mimo_v2_omni) ДО монтирования замен, плюс
  provenance SHA-256 заменяемых оригиналов. Смена digest образа ловится до
  13-16-минутной загрузки модели, а не после.
* Полнота валидации (P2): `HOTSPLIT_HOST_FLOOR_GIB` и
  `HOTSPLIT_VRAM_RESERVE_GIB` проверяются как неотрицательные дробные; для
  целочисленных — диапазоны (DYN_STEPS/TOPK/LIVE_SECS/DECODE_MAX/лимиты
  ошибок >= 1, DYN_MAX_SWAPS 1..1024 — границы самого план-кода);
  MAX_TOKENS / DYN_PRIOR_TOKENS допускают 0.
* Честность про счётчики тестов: sandbox-прогоны (346+2 / 338+5) и CI-прогоны
  (344+4 / 336+7) различаются, потому что в CI нет необязательных зависимостей
  (wiki checkout, lz4-биндинги). В доках приведены CI-цифры; оба набора
  зелёные.

## Раунд 60 (путь модуля в CI, эквивалентность BOOT_HOOK, полная валидация)

* CI kv-persistence теперь клонирует `sikkatu/recipes` (в `recipes/`), а
  тестовый хелпер ищет общий модуль `hotsplit_env.sh` СНАЧАЛА относительно
  checkout (пути домашних каталогов разработчика остаются запасными) — два
  теста, падавшие в каждом CI-прогоне, теперь читают настоящий модуль.
* `HOTSPLIT_BOOT_HOOK` больше не принудительно равен 1: при смонтированных
  model-патчах заменённый `mimo_v2_hotsplit.py` уже вызывает
  `hotsplit.apply_hotsplit`, поэтому лаунчер по умолчанию ставит boot hook = 0 —
  то же решение, что принимает лаунчер рецепта (нет двойной обёртки одного
  загрузчика). Health-check активации следует настроенному значению:
  `boot_hook=INACTIVE` — ПРАВИЛЬНОЕ состояние при 0.
* Хост-валидация HotSplit теперь покрывает все числовые knobs общего модуля:
  DYN_STEPS, DYN_MAX_SWAPS, DYN_PRIOR_TOKENS, MAX_TOKENS, TOPK,
  LIVE_DECODE_MAX, DYN_MAX_PLAN_ERRORS, DYN_MAX_COMMIT_ERRORS,
  VRAM_RESERVE_GIB, LIVE_SECS (последние шесть раньше не проверялись).
  Регрессионные тесты закрепляют все три исправления.
