# Журнал изменений

Все заметные изменения kv-persistence, новые сверху. Здесь хранятся только
последние 3 раунда (запрос пользователя) — полная история правок в
git-логе ветки `main`.

Версии языков: [English](CHANGELOG.md) | **Русский** | [中文](CHANGELOG.zh.md)

## Не выпущено

Runtime: закреплённый образ vLLM (`@sha256:167ccd86…`) + **LMCache 0.5.6** (`requirements-lmcache.txt`).


## Раунд 63 (паритет парсера, ключ вне ps, монтирование /live, kvp CLI)

* `_tp4_seed` в лаунчере движка теперь побайтово идентичен парсеру рецепта:
  `$HOME`/`${HOME}` раскрываются, окружающие кавычки снимаются, инлайн-коммент
  режется только на " #", а строки без валидного идентификатора (комментарий с
  отступом) пропускаются вместо падения "invalid variable name".
* API-ключ больше не появляется в выводе `ps` (все 5 лаунчеров рецепта,
  KV-лаунчер и test-recovery.sh): он передаётся через `docker --env-file`
  (chmod 600) и `curl -K`, а не аргументами `-e VLLM_API_KEY=<значение>` и
  `-H "Authorization: Bearer ..."`.
* В KV-лаунчере монтируется `/live` (`$ROOT/live:/live`), чтобы счётчики
  маршрутизации сохранялись; проверка активации теперь также падает на
  "live snapshot failed" и проверяет `HOOK STATUS numa_bind=ACTIVE` при
  включённом NUMA-биндинге.
* Миграция ключа реально записывает канонический `~/.config/kvp/api_key`
  (обещание "migrate below" в `_kvp_load_api_key` не было реализовано — два
  репо пользовались разными ключами).
* `USE_LOSSLESS_SERDE`/`LMCACHE_L2_SERDE` из tp4.env теперь доходят до единого
  решения по кодеку (start-all сидирует tp4.env ДО резолва), а
  пользовательский `VLLM_EXTRA_ARGS` больше не убирает молча MiMo-парсеры
  (отключение: `KVP_MIMO_PARSERS=0`).
* Добавлен файл пина `KVP_COMPAT_VERSION` в kv-persistence (лаунчер рецепта
  его уже проверял); принимаются оба имени `KVP_REPO`/`KVP_REPO_ROOT`.
* CLI `kvp` на PATH (`scripts/install-kvp.sh` -> `~/.local/bin/kvp`):
  `kvp up|down|status|logs`, расположения репо запоминаются в `~/.config/kvp/`.
* Устаревшие доки исправлены (README EN/RU/ZH + комментарии lmcache-server.env):
  пропуск переменной даёт lossless-zstd, raw требует явного
  `LMCACHE_L2_SERDE=none`.
* Тесты: проверки лаунчеров рецепта теперь следуют контракту env-file (ключ
  НЕ должен быть аргументом командной строки) и учитывают раскладку `~/recipes`.

## Раунд 62 (диапазоны float-параметров + свежие CI-цифры)

* Валидация float-параметров теперь проверяет НАСТОЯЩИЕ диапазоны план-кода
  на хосте: `HOTSPLIT_DYN_DECAY` — 0..1, `HOTSPLIT_DYN_MARGIN` — не меньше 1
  (границы `_dyn_float` в hotsplit.py). Раньше проверялся только числовой
  формат, поэтому `DYN_DECAY=2` / `DYN_MARGIN=0.5` проходили хост-проверку и
  отвергались внутри контейнера после загрузки модели. Диапазоны считаются на
  чистом bash (без внешних утилит, без fail-open).
* CI-цифры обновлены после фикса cross-repo пути: CI recipes теперь
  **336 passed + 7 skipped** (в примечании раунда 61 было 330+13);
  CI kv-persistence без изменений — 344 passed + 4 skipped. Доки ссылаются на
  актуальные цифры.

## Раунд 61 (путь cross-repo в CI, эквивалентность boolean, compatibility probe)

* Контрактные тесты между репозиториями в CI recipes теперь реально
  выполняются: тест сначала ищет checkout kv-persistence ВНУТРИ workspace
  (`RECIPES/kv-persistence`, раскладка GitHub Actions) и лишь потом в
  домашних путях разработчика. Шесть контрактных тестов больше не
  пропускаются в CI.
* Boolean-параметры HotSplit нормализуются в KV-лаунчере ровно как в
  лаунчере рецепта (`normalize_bool`: true/yes/on -> 1, false/no/off -> 0)
  ДО подключения общего модуля. Компоненты HotSplit сравнивают со строкой "1"
  (`HOTSPLIT_NUMA == "1"`), поэтому сырое `true` незаметно отключало функцию.
  Покрыты DYNAMIC / DRYRUN / NUMA / ALLOW_STATIC_FALLBACK / STRICT_HOOK /
  NUMA_STRICT / DYN_LOG.
* KV-лаунчер теперь выполняет ТОТ ЖЕ compatibility probe model-патчей, что и
  лаунчер рецепта (сшивка base_loader, определение model_loader.utils,
  `load_weights` у mimo_v2/mimo_v2_omni) ДО монтирования замен, плюс
  provenance SHA-256 заменяемых оригиналов. Смена digest образа ловится до
  13-16-минутной загрузки модели, а не после.
* Полнота валидации (P2): `HOTSPLIT_HOST_FLOOR_GIB` и
  `HOTSPLIT_VRAM_RESERVE_GIB` проверяются как неотрицательные дробные; для
  целочисленных — диапазоны (DYN_STEPS/TOPK/LIVE_SECS/DECODE_MAX/лимиты
  ошибок >= 1, DYN_MAX_SWAPS 1..1024 — границы самого план-кода);
  MAX_TOKENS / DYN_PRIOR_TOKENS допускают 0.
* Честность про счётчики тестов: sandbox-прогоны (346+2 / 338+5) и CI-прогоны
  (344+4 / 336+7) различаются, потому что в CI нет необязательных зависимостей
  (wiki checkout, lz4-биндинги). В доках приведены CI-цифры; оба набора
  зелёные.
