## Раунд 76 (ложный SIGPIPE в проверке активации, общая валидация конфига, покрытие TP)
* Проверка активации врала на больших логах движка (ревью, воспроизведено на
  железе): `printf '%s' "$log" | grep -q ...` под `set -o pipefail` --
  `grep -q` завершается на первом совпадении и закрывает пайп, `printf`
  получает SIGPIPE (141), пайплайн «неуспешен» и `if` идёт в ветку «не
  найдено», хотя маркер в логе ЕСТЬ. На 17-минутном логе загрузки ВСЕ четыре
  маркера читались [MISSING] при исправном движке -- а те же пайпы охраняли
  проверки ОШИБОК, и настоящая ошибка могла пройти как успех. Все 8 мест
  (по 4 в лаунчерах) теперь на here-string
  (`grep -q -- "..." <<<"$log"`) -- без пайпа, без SIGPIPE. Регрессионные
  тесты на 100 КиБ-логе покрывают оба направления (маркеры есть → VERIFIED;
  ошибки/маркеры в правильной комбинации → правильный вердикт).
* Валидация конфига HotSplit перенесена в ОБЩИЙ модуль
  (`hotsplit_env.sh::_hotsplit_validate_config`): проверки (формат NUMA_MAP,
  DYN_DECAY 0..1, DYN_MARGIN ≥ 1, DYN_MAX_SWAPS 1..1024, целочисленные и
  float-ручки) жили ТОЛЬКО в kv-лаунчере -- после переключения пути движка
  на рецептный они бы исчезли. Оба лаунчера теперь вызывают одну функцию.
* НОВАЯ проверка (ревью): HOTSPLIT_NUMA_MAP должен ПОКРЫВАТЬ каждый ранг
  GPU 0..TP-1. `numa_bind.py` молча возвращает -1 для отсутствующего GPU и
  при этом сообщает `numa_bind=ACTIVE` -- карта "0:0,1:0" на TP4 привязывала
  2 из 4 GPU и выглядела здоровой. Валидатор теперь называет каждый
  недостающий ранг. Поведенческие тесты (TP4/TP2) в
  `tests/test_hotsplit_validation.py` -- условие переключения дефолта на
  рецептный лаунчер.
* Согласие на override namespace (раунд 73) теперь покрыто:
  `tests/test_namespace_override_consent.py` -- без
  `KVP_ALLOW_NAMESPACE_OVERRIDE=1` унаследованный `KVP_MODEL_NAME`
  ИГНОРИРУЕТСЯ с громким WARNING (имя из identity побеждает); с флагом
  override применяется, тоже с WARNING.
## Раунд 74 (прогон на железе, шаг 1: валидатор NUMA_MAP + честный NOTE про промоушен)
* Валидатор HOTSPLIT_NUMA_MAP отвергал ПРАВИЛЬНОЕ значение (блокер прогона):
  regex требовал `node:cpu,cpu;node:cpu` ('0:0,1,2,3;1:4,5,6,7'), тогда как
  реальный потребитель (`patches/numa_bind.py map_from_env`) парсит пары
  `gpu:node` через запятую -- ровно формат из `tp4.env.example`
  ('0:0,1:0,2:1,3:1'). Правильная карта обрывала запуск с «nothing was
  started». Валидатор теперь принимает реальный формат (строго), сообщение
  об ошибке его показывает. Добавлен регрессионный тест.
* NOTE про промоушен врал про `auto`: «engine, namespace and gate will all
  use KV_CACHE_DTYPE=auto» вводит в заблуждение -- `auto` резолвится в
  dtype МОДЕЛИ из config.json ДО старта движка и ДО хеширования namespace
  (для bf16-модели это совпадает с закреплённым bfloat16 -- ТОТ ЖЕ namespace
  кэша). Теперь NOTE объясняет резолв.
