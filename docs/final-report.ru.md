# Итоговый отчёт — kv-persistence

Репозиторий: github.com/sikkatu/kv-persistence (ветка `main`,
коммит `HEAD` (см. `git rev-parse HEAD`) — верифицирован через GitHub remote API).

## Общий статус: PARTIAL

Реализация завершена, офлайн-тесты зелёные (70 unit-тест, включая 3 P0-регрессии
хеширования весов, паритет конфигов, бюджет и retention).
Аппаратные приёмочные сценарии (A/B восстановления после рестартов, бенчмарки
32K/128K/256K, bytes-per-token) подготовлены как скрипты (`scripts/test-recovery.sh`,
`scripts/benchmark.sh`) и предназначены для прогона на GPU-хосте пользователем или внешними ревьюерами. Статус PARTIAL — единственно
честная метка до прогона на железе: ничего не протестированного не числится
работающим.

## Архитектура и выбранный бэкенд

```
Клиент чата → vLLM (TP4, prod-рецепт не изменён) → LMCacheMPConnector
            → лаунчер kv-persistence (пакет kvpersist + скрипты) → NVMe
```

Уровень хранения — LMCache `nixl_store_dynamic` + POSIX (persist_enabled=true,
детерминированный файл на ключ чанка, ленивое восстановление индекса после
рестарта ОБОИХ процессов; max_capacity_gb = 1500 ГБ по умолчанию, LRU-эвикция
с мягким порогом 0.9).

## Изоляция по идентичности на уровне хранилища LMCache (review P1-3)

Namespace идентичности теперь принудительно разделяет данные в РЕАЛЬНОМ
хранилище LMCache, а не только в локальных метках. Проверено по исходникам
закреплённого LMCache 0.5.3 и живым прогоном запись/поиск (интеграционный тест
`test_identity_namespace_isolates_lmcache_storage`, см. docs/benchmarks.ru.md):

* Ключ кэша LMCache (`ObjectKey.model_name`) входит и в ключ, и в имя файла L2
  адаптера `nixl_store_dynamic`
  (`<safe_model_name>_<kv_rank>_<group>_<chunkhash>.bin`).
* `CacheIdentity.lmcache_model_name()` встраивает namespace в этот
  `model_name`, поэтому изменение ЛЮБОГО поля идентичности переносит данные на
  другой ключ И в другой файл на диске. Доказано по каждому полю: поиск
  изменённой идентичности возвращает `0/N` чанков на уровне API LMCache там,
  где исходная возвращает `N/N`.
* **Остаточный пробел (измерен, закреплён тестом)**: `cache_salt` входит в
  равенство ключа, но НЕ входит в имя файла `nixl_store_dynamic` (адаптеры
  fs/s3/bigtable его учитывают). После рестарта вторичный (дисковый) поиск тех
  же токенов под ДРУГОЙ солью может вернуть объекты исходной соли — измерено
  живым прогоном: `store salt=tenantA`, `lookup salt=tenantB` -> `4/4` чанка.
  Пока upstream не включит соль в имя файла, НЕ полагайтесь на `cache_salt`
  для изоляции на уровне L2: встраивайте пер-тенантный дискриминатор в
  `lmcache_model_name(extra_discriminator=...)` или используйте отдельный корень
  L2-кэша на тенанта. Тест
  `test_cache_salt_isolation_gap_in_nixl_store_dynamic` громко падает, если
  upstream это исправит.

## Идентичность весов — P0-исправление

Новая реализация `scripts/setup-identity.sh` хеширует СОДЕРЖИМОЕ каждого шарда
(SHA-256), а не только имя+размер. Прогнан смоук: байтовая подмена шарда при
неизменных имени и размере теперь меняет отпечаток (`pytest
tests/unit/test_fingerprint_content.py` — 3 регрессионных зелёных). Кэш хешей
шардов ускоряет повторные запуски. Режим `fast` (только имя+размер) доступен
через `KVP_FINGERPRINT_MODE=fast` с явным предупреждением о риске — не для проды.

## Проверка идентичности движка — обязательный барьер

`scripts/verify-engine-identity.sh` (вызывается перед использованием кэша в
`test-recovery.sh`) — сверяет пины identity.env с реальными аргументами
движка (через `docker inspect`) и геометрией модели из config.json.
Три исхода: VERIFIED(0) / MISMATCH(4) / INCONCLUSIVE(5).
**INCONCLUSIVE = отказ от переиспользования кэша**, а не «ошибок нет, значит ок».

## Тест восстановления — протокол v2 (по замечаниям ревью)

* Маркеры позиции лога до каждого запроса — только свежие события считаются.
* Store-before-restart: блоки должны быть реально записаны в L2 до рестарта.
* Различие L2 (диск) от L1 (RAM) в доказательствах чтения.
* cached_tokens == `null` обрабатывается: MISSING → INCONCLUSIVE, а не «отсутствие
  попадания» по умолчанию.
* Физические счётчики чтения с NVMe (`/sys/block/<dev>/stat`) как независимое
  подтверждение логов (при заданном `KVP_CACHE_DEVICE`; без него — INCONCLUSIVE).
* Три-состоятельный вердикт: PASS(exit 0) / INCONCLUSIVE(exit 5) / FAIL(exit 1).

## Правки по итогам ревью, раунд 13 (проверено на этом хосте)

* `setup-identity.sh` больше не записывает значения в кавычках (его же проверка
  падала с `got '"76ce..."'`); кавычки снимаются и при чтении.
* `run-vllm-with-persist.sh`: гейт идентичности выполняется ДО запуска как
  проверка только конфига (`--check-config-only`) и ПОСЛЕ `docker run` по
  аргументам НОВОГО контейнера (раньше проверялся ещё не созданный контейнер
  или устаревшие аргументы). `KVP_PERSIST_ENABLED=0` честно пропускает оба гейта.
* Изоляция по идентичности теперь действует в РЕАЛЬНОМ пути vLLM: модель
  монтируется в `/models/<lmcache_model_name>` (имя кодирует namespace), поэтому
  `model_config.model` — значение, из которого LMCache строит ObjectKey и имена
  файлов L2 — различается между идентичностями (раньше везде был `--model /model`).
* `kvpersist.cli` видит реальную раскладку L2 (плоские `*.bin` файлы адаптера):
  `status` считает их байты, `purge --all` и `emergency-evict` реально удаляют их.
  Дефолт бюджета — 1500 ГБ (был 750). `KVP_CACHE_ROOT`/`KVP_CACHE_BUDGET_GB`
  читаются из конфигов репозитория, поэтому `emergency-evict` работает из cron.
  Квоты задокументированы как только отчётные (не подключены к пути записи).
* systemd-юниты: `lmcache-server.service` (обычный, `User=kvp`) и
  `lmcache-server@.service` (шаблонный, `User=%i` — единственная допустимая
  форма для `%i`), плюс wrapper `systemd/kvp-lmcache-server`, передающий
  отрендеренный JSON адаптера инлайном (`--l2-adapter` принимает JSON-строку).
* `test-recovery.sh`: жёсткие FAIL больше не затираются INCONCLUSIVE (счётчики
  `V`/`VI` разделены, FAIL имеет приоритет); холодный префикс получает nonce
  каждого прогона, чтобы повторный запуск был по-настоящему холодным.
* Docker-режим: `--help` опрашивается внутри контейнера, сервер слушает `0.0.0.0`
  внутри него (на хосте порты по-прежнему только loopback), добавлены
  `--gpus all --ipc host`, строка лога больше не падает на незаданной переменной.
* `retention.py`: линейный член по длине префикса (версия с `log1p` вытесняла
  длинные переиспользуемые префиксы первыми); `min_keep_tokens` документирован
  как единственная прямая защита. `prompt_probe.py` сериализует
  `tool_calls`/`tool_call_id`.
* `preflight.sh`: вывод `lsblk -p` больше не даёт имена вида `/dev//dev/...`.
  Файл `.commitmsg11` удалён из дерева.

## Правки по итогам ревью, раунд 14 (проверено на этом хосте)

* **КРИТИЧНО**: `run-vllm-with-persist.sh` не передавал `--block-size`, поэтому
  пост-запусковой гейт идентичности никогда не мог проверить `block_size`
  (INCONCLUSIVE, exit 5), и лаунчер тут же делал `docker rm -f` собственного
  контейнера. Теперь vLLM передаётся `--block-size "${KVP_BLOCK_SIZE:-16}"`
  (гейт в `test-recovery.sh` тоже проходит — он проверяет тот же контейнер).
* `l2_serde` теперь реально входит в namespace идентичности: `model-name` читает
  generic-слои конфигов (где живёт `LMCACHE_L2_SERDE`) в том же порядке, в
  котором их сеет bash-загрузчик, поэтому `none` и `fp8` дают РАЗНЫЕ имена.
  Переменная окружения ПОБЕЖДАЕТ файлы (как в `scripts/env.sh`).
* `purge --namespace` сопоставляет namespace ТОЧНЫМ совпадением. Реальные
  пространства выглядят как `--models--MyModel--<hash>` (начинаются с дефиса),
  поэтому в доках показана форма `--namespace=NAME` (или новая позиционная);
  `--namespace NAME` argparse распознаёт как неизвестную опцию. При
  отсутствии совпадений — exit 1 с сообщением. Имена файлов с `_` парсятся
  право-якорным regex (`my_model` больше не обрезается до `my`).
* `retention.py`: вес попаданий стал существенным. Формула —
  `(hits + 1) × tokens × свежесть ÷ байты`. При постоянных байтах на токен она
  нейтральна к длине при равных hits (прежняя `log1p` вытесняла длинные
  префиксы первыми; предыдущая `3*hits + 1.5*tokens` давала hits ~1% выгоды).
  Чтобы явно отдать предпочтение длинной записи — поднимите `min_keep_tokens`
  или добавьте малую положительную степень `tokens`.
* Загрузчики конфигов совпадают байт-в-байт по приоритету: Python-загрузчик
  применяет файлы в том же порядке, что bash-сидеер (cache.env ->
  lmcache-server.env -> identity.env -> *.local).
* systemd: `kvp-lmcache-server` имеет режим 100755 с инструкциями установки;
  рендерит L2-спеку по требованию и читает `cache.env`/`.local` для
  `KVP_CACHE_ROOT` и бюджета (та же приоритетность, что у `start-cache.sh` —
  кастомный корень кэша из `cache.env.local` учитывается, без тихих 1.5 ТБ на
  системном диске); `StateDirectory=kv-persistence` решает права для пути по
  умолчанию; для кастомного `KVP_CACHE_ROOT` выполните
  `sudo install -d -o kvp -g kvp -m 0700 <dir>`; `KVP_REPO_ROOT` по умолчанию
  `/home/kvp/kv-persistence` (README клонирует в `~/kv-persistence`;
  переопределение — в `/etc/kv-persistence.env`).
* Синхронизация доков (EN/RU/ZH): формулы `eviction-and-deduplication.*`
  обновлены до линейной формы; `storage-management.*`, `security.*` и
  `final-report.*` описывают реальную раскладку L2 (плоские файлы
  `<safe_model_name>_<rank8>_<group>_<hash64>.bin`) вместо несуществующих
  каталогов `kvp-<hash>`; в `deployment.*` добавлен systemd-раздел с правами и
  формой `--namespace=NAME`.
